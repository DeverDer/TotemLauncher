# Как выложить TotemLauncher на GitHub и выпускать обновления

## Как это устроено
- Лаунчер, установщик и обновления живут в **публичном** репозитории GitHub, во вкладке **Releases**.
- У каждого выпуска есть **тег** вида `v0.15.0` (цифры через точки, перед ними `v`). Каждый следующий выпуск должен иметь номер **больше** предыдущего.
- В релиз попадают три файла (их собирает GitHub сам, см. ниже):
  - `TotemLauncher-Setup.exe` — установщик для нового компьютера;
  - `TotemLauncher-<версия>-win-x64.zip` — сам лаунчер (его скачивают установщик и обновление);
  - `TotemLauncher-<версия>-win-x64.zip.sha256` — контрольная сумма.
- Установщик берёт **последний** релиз, распаковывает лаунчер в `<папка>\app-<версия>` и создаёт ярлыки. Лаунчер при **каждом запуске** проверяет, нет ли релиза новее, и предлагает обновиться.

## 1. Первый раз
1. Зарегистрируйтесь на github.com и включите двухфакторную защиту (Settings → Password and authentication). Тот, кто владеет репозиторием, может выпустить обновление для всех ваших пользователей — берегите аккаунт.
2. Нажмите **New repository**: имя `TotemLauncher`, видимость **Public** (для закрытого репозитория обновления не работают), галочки README/.gitignore не ставьте → **Create repository**.
3. Загрузите проект (распакованную папку из архива). Самый простой способ — **GitHub Desktop** (desktop.github.com): `File → Add local repository…` → выберите папку проекта (если спросит «создать репозиторий» — согласитесь) → `Publish repository` (снимите галочку Private). Либо в командной строке:
   ```
   cd путь\к\папке\TotemLauncher
   git init
   git add .
   git commit -m "TotemLauncher 0.15.0"
   git branch -M main
   git remote add origin https://github.com/DeverDer/TotemLauncher.git
   git push -u origin main
   ```
   Папки `node_modules` и `dist` загружать не нужно — они в `.gitignore`. Обязательно должна попасть папка `.github` (в ней сборочный сценарий).
4. В репозитории: **Settings → Actions → General → Workflow permissions → Read and write permissions → Save**.
5. Первый выпуск: вкладка **Actions** → слева **Release** → кнопка **Run workflow** → в поле введите `v0.15.0` → **Run workflow**. Сборка идёт 10–15 минут. Зелёная галочка — готово; красный крест — откройте запуск, скопируйте текст ошибки.
6. Вкладка **Releases** → `v0.15.0`: там три файла. Ссылка, которую можно давать другим для скачивания установщика (она всегда ведёт на последний):
   `https://github.com/DeverDer/TotemLauncher/releases/latest/download/TotemLauncher-Setup.exe`

   Установщик уже знает репозиторий — пользователю ничего вводить не нужно, и в самом установщике слов про GitHub нет.

## 2. Как выпустить обновление
1. Внесите изменения в проект и отправьте их в репозиторий (GitHub Desktop: `Commit to main` → `Push origin`; или правка файла прямо на сайте).
2. **Actions → Release → Run workflow** → новый тег, например `v0.16.0` (строго больше предыдущего, формат `vX.Y.Z`; `v0.16`, `0.16.0` и `v0.16.0-beta` не подойдут). Номер версии в `package.json` менять не нужно — сборка берёт его из тега.
3. Через 10–15 минут релиз появится на странице Releases. При следующем запуске лаунчера у пользователей откроется окно обновления.
4. Текст релиза (Releases → Edit) показывается в окне обновления (первые 1500 символов) — напишите там, что нового.

Нельзя: удалять файлы из выпущенного релиза, помечать релиз как *pre-release* или *draft* (такие не считаются «последними»), выпускать версию меньше или равную предыдущей. Если нужно откатиться — выпустите **новый** номер со старым кодом.

## 3. Без сборки на GitHub (вручную)
Файлы можно собрать и на своём Windows-компьютере: установите Node.js 20 LTS, затем в папке проекта:
```
npm install
set TOTEM_REPO=DeverDer/TotemLauncher        (PowerShell: $env:TOTEM_REPO="DeverDer/TotemLauncher")
npm run dist
```
Файлы появятся в `dist\` (`dist\installer\TotemLauncher-Setup.exe`). Номер версии берётся из `package.json` (поле `version`). Затем **Releases → Draft a new release → Choose a tag** (введите `v0.15.0` → Create new tag) → прикрепите `.zip`, `.zip.sha256` и `TotemLauncher-Setup.exe` (имена менять нельзя) → **Publish release**.

Установщик и лаунчер уже знают свой репозиторий (`DeverDer/TotemLauncher`) — пользователю ничего вводить не нужно.

## 4. Что увидит пользователь
- **Чистый компьютер:** открывает `TotemLauncher-Setup.exe` → выбирает папку (по умолчанию `C:\Users\<имя>\AppData\Local\Programs\TotemLauncher`) → «Начать установку» → полоса прогресса с процентами и «X МБ из Y МБ» → «Завершить» (галочка «Запустить лаунчер после установки» включена по умолчанию). На рабочем столе и в меню «Пуск» появляются ярлыки.
- **Лаунчер уже установлен:** установщик сам это видит, сравнивает версии и предлагает «Обновить» (или сообщает, что установлена последняя).
- **Дальше обновления идут из самого лаунчера:** при каждом запуске он проверяет GitHub. Если есть новая версия — окно «Доступно обновление» с описанием; «Обновить» скачивает, устанавливает и перезапускает лаунчер. «Позже» можно нажать 3 раза для одной версии, после этого обновление обязательное. В **Настройках → Обновления лаунчера** есть кнопка «Проверить на обновления» и показана последняя версия.
- Данные (аккаунты, настройки, миры, скачанные версии игры) лежат в `%APPDATA%\totem-launcher` и при обновлении не затрагиваются. Старая версия лаунчера удаляется при первом запуске новой.
- Деинсталлятора нет: чтобы удалить лаунчер, удалите папку установки и ярлыки (данные в `%APPDATA%\totem-launcher` — по желанию).

## 5. Если что-то не работает
- **Windows: «SmartScreen: Windows защитила ваш компьютер»** — установщик не подписан цифровым сертификатом (он платный). Нажмите «Подробнее → Выполнить в любом случае». Антивирусы иногда реагируют так же на любые неподписанные программы.
- **«Обновления работают только в установленной версии»** — лаунчер запущен не из установленной копии (например, `npm start`). Поставьте его установщиком.
- **«В репозитории нет опубликованных релизов»** — репозиторий закрытый или релиз ещё не создан/не завершилась сборка.
- **«В релизе нет файла TotemLauncher-X-win-x64.zip»** — сборка ещё идёт или файл удалён/переименован.
- **«GitHub временно ограничил запросы»** — подождите несколько минут (лимит для запросов без входа).
- **Не хватает места / нет прав на запись** — выберите другую папку (лучше внутри профиля пользователя, не `Program Files`).
- Подробности пишутся в журнал: `%APPDATA%\totem-launcher\logs\launcher.log`.

## 6. Безопасность
- Обновление скачивается только по https с `github.com` вашего репозитория и проверяется по SHA-256 (его считает сам GitHub). Файл с неверной суммой не устанавливается.
- Все, у кого есть право записи в репозиторий, могут выпустить обновление для всех. Не давайте доступ посторонним, не храните в репозитории пароли и ключи, держите включённой двухфакторную защиту.

## 7. Выпуск обновления (пошагово, до каждой кнопки)
0. Откройте `package.json` и посмотрите строку `"version"`. Это номер нового выпуска (сейчас `0.16.0`). Он должен быть **больше**, чем у прошлого релиза на GitHub, иначе у пользователей не появится окно «Доступно обновление». Поменяли номер — ниже везде подставляйте его вместо `0.16.0`.
1. Откройте github.com/DeverDer/TotemLauncher. Убедитесь, что вы вошли в аккаунт.
2. Загрузите новые файлы проекта. Самый надёжный способ — GitHub Desktop:
   1. Распакуйте `TotemLauncher_совмещённый.zip` **поверх** папки проекта, которую вы уже подключали к GitHub Desktop (согласитесь заменить файлы). Папку `.git` не трогайте.
   2. Откройте GitHub Desktop → слева появится список изменённых файлов.
   3. Внизу слева в поле «Summary» напишите `Обновление 0.16`.
   4. Нажмите синюю **Commit to main**.
   5. Вверху нажмите **Push origin**. Подождите, пока кнопка не станет серой.
   Через сайт: **Add file → Upload files** → перетащите **содержимое** распакованной папки (все папки и файлы, включая скрытую `.github`) → внизу **Commit changes**.
3. Проверьте вкладку **Code**: там должны быть новые файлы `src/diagnose.js`, `src/errlog.js`, `tools/make-icons.py` и обновлённая дата у остальных.
4. Откройте вкладку **Actions** → слева **Release** → справа **Run workflow** → в поле tag введите `v0.16.0` → зелёная **Run workflow**.
5. Подождите 10–15 минут (обновите страницу клавишей F5). Зелёная галочка — готово.
6. Вкладка **Releases** → `v0.16.0` должен быть помечен **Latest**, в нём три файла: `TotemLauncher-Setup.exe`, `TotemLauncher-0.16.0-win-x64.zip`, `TotemLauncher-0.16.0-win-x64.zip.sha256`.
7. Нажмите **Edit** у релиза и напишите в описании, что нового (это видно пользователям в окне обновления): например «Новая вкладка Сборки, выбор сборки в каталоге, поиск проблемных модов, скин Ely.by, новая иконка».
8. Проверка у себя: запустите установленный лаунчер — через несколько секунд должно появиться окно «Доступно обновление». Нажмите «Обновить».
9. Если красный крест на сборке: откройте запуск → задание **build** → раскройте шаг с ✗ → скопируйте последние строки ошибки и пришлите мне.
