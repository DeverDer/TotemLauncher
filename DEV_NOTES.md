# TotemLauncher — заметки для разработки (читать первым)

Лаунчер Minecraft Java для Windows на Electron. Запуск: `npm install && npm start`. Сборка portable-exe: `npm run dist` → `dist/TotemLauncher.exe`. Тесты: `npm test` (Linux, пишут в /tmp).

## Структура
- `src/main.js` — главный процесс: окна (первый запуск → загрузка → главное), IPC, настройки (`%APPDATA%/totem-launcher/settings.json`), аккаунты, время в игре.
- `src/preload.js` — мост `window.totem.*` (каждому методу соответствует `ipcMain.handle/on` в main.js).
- `src/game.js` — установка версий Mojang, Java (рантайм Mojang), запуск, Forge/NeoForge/Fabric, загрузчик файлов (`runTasks`, sha1, отмена). Быстрый запуск без сети, если есть маркер `.installed`.
- `src/instances.js` — сборки (свои папки mods/resourcepacks/shaderpacks/saves), список файлов, архив модов, точки восстановления, проверка совместимости.
- `src/compat.js` — диапазоны версий (semver Fabric и maven Forge), формат ресурс-пака, версия мира (NBT).
- `src/catalog.js` — Modrinth (моды, ресурс-паки, шейдеры, датапаки, .mrpack) и CurseForge (карты, нужен API-ключ), зависимости, буст FPS, OptiFine с optifine.net.
- `src/ely.js`, `src/auth.js` — Ely.by (Yggdrasil + authlib-injector) и Microsoft (закрыт флагом `MS_LOCKED` в main.js).
- `src/skinpack.js` — скин локального аккаунта в игре через ресурс-пак TotemSkin.zip; `src/skins.js` — хранение скинов; `src/shots.js` — скриншоты; `src/fm.js` — файловый менеджер (только внутри папки данных).
- `src/ui/` — интерфейс без сборщика: `main.html`, `app.js` (вся логика), `app.css`, `skin.js` (3D-персонаж на WebGL, анимации), `icons.js` (пиксельные иконки в коде), `bg.js` (фоны), `assets/`.

## Несколько окон игры (v0.13)
- `Game._run(ctx, …)` — общий конвейер запуска. `ctx` = сам `Game` (основное окно `main`) или объект окна из `Game.openWindow()` (`w2`, `w3`…). Состояние окон: `Game.list()` → событие `wins:state` → `totem.onWins`. Остановка: `stopWin(id)` / `stopAll()` (в интерфейсе — меню на кнопке «Остановить», если окон больше одного).
- Подготовка/загрузка окон идёт по очереди (`_lock`): два окна не качают одни файлы одновременно. Запуск (spawn) — параллельный.
- Память: `splitRam(ОЗУ из настроек, число окон)`, минимум 1024 МБ. Уже запущенные окна память не меняют (Xmx фиксируется при старте) — это показано в предупреждении. Основное окно, запущенное при работающих дополнительных, тоже получает долю.
- Одноразовый ник и скин окна не пишутся в настройки. Скин доп. окна — отдельный пак `resourcepacks/TotemSkin-N.zip` (основной `TotemSkin.zip` не трогаем: Windows держит его открытым); в `options.txt` всегда ровно один наш пак (`optionsText` чистит остальные), при закрытии окна пак удаляется.
- Все окна используют одну папку игры (общие миры). Natives уже запущенной версии не перераспаковываются (DLL заблокированы).
- Время в игре считается, пока открыто хотя бы одно окно (`syncPlay` в main.js). Файловые операции блокируются, пока активно любое окно (`game.active`).

## Каталог: что учесть
- `jget/tget` повторяют запрос 3 раза (сетевые сбои, 429/5xx), таймаут 25 с. «Нет интернета» показывается только если не отвечают оба тестовых сервера (`online()`), иначе — настоящая причина.
- Ключ CurseForge чистится (`cleanKey`), 401/403 даёт понятное сообщение и снова открывает ввод ключа; кнопка сохранения проверяет ключ запросом `/games/432`.
- Скачанное записывается в `<сборка>/.totem-catalog.json`; «уже скачан» = файл реально есть (mods, `.disabled` или `mods-archive`). Повторная установка отклоняется и в `cat:install`.
- Слои: `.modal` — flex (не grid: процентная высота панели в grid раздувала каталог); подтверждения/выбор сборки z-index 100, прогресс 105, уведомления 120. Вместо системного `confirm()` — `ask()` (после `confirm` в Electron поля ввода теряют фокус).

## Безопасность (v0.14) — что держать в голове
- Окна: `sandbox:true`, `contextIsolation`, CSP в каждом html (`script-src 'self'`, без инлайн-скриптов/обработчиков — для картинок есть делегированный `error`-обработчик), запрет навигации/`window.open`/webview, запрос не к `file:`/`data:`/известным CDN картинок блокируется (`hardenSession`). IPC принимается только от страниц из `src/ui/` (обёртка `ipcMain` в main.js).
- Любой новый IPC-обработчик: валидировать вход (id версии — `VID`, id проектов/типы/загрузчики — `catIn`, имена файлов — `FM.name`/`Instances.safe`). Пути проверять через `within()` (с разделителем), а не `startsWith(root)`.
- Загрузки: только https (http — лишь localhost для тестов), редирект на http отклоняется, лимит размера, таймаут простоя 30 с, sha1 где он есть. Модпаки/архивы: `badRel()` (абсолютные пути, `..`, `C:`, `:stream`, CON/NUL…), лимиты файлов/байт.
- Ссылки наружу: `safeWeb` (https + curseforge/modrinth/optifine/ely), без `cmd /c start`. `fm:open` запускает только безопасные расширения, остальное показывает в папке.
- Настройки: `javaPath` — только java/javaw; `jvmArgs` без `-javaagent/-cp/-agentlib/@file…` (`Game.badJvm`, проверка и при сохранении, и при запуске).
- Ely.by: authlib-injector только с sha256 и известного хоста, кэш перепроверяется; токен — `safeStorage`; при удалении аккаунта токен отзывается.
- Тесты безопасности: `tests/security.js`; ручной прогон в настоящем Electron делался скриптами на Playwright `_electron` под Xvfb (настройки, сборки, файлы, скины, каталог с подменой сети, окна игры с фейковой Java).
- Стартовая проверка `stages[0]` проверяет реально существующие файлы (раньше требовала удалённый `common.css` — чистая установка не запускалась).

## Установщик и самообновление (v0.15)
- Схема установки: `<папка>/app-<версия>/TotemLauncher.exe`; `install.json` лежит и в папке установки, и в `%LOCALAPPDATA%\TotemLauncher`. Новая версия распаковывается в СОСЕДНЮЮ папку (Windows не даёт перезаписывать запущенные файлы), ярлыки переписываются, процесс перезапускается с `--wait-pid=<старый pid>` (иначе блокировка единственного экземпляра закроет новый). Старые `app-*` удаляет новая версия при запуске (`cleanupOld`).
- `src/updater-core.js` — общее ядро (GitHub API, скачивание с SHA-256, свой асинхронный разбор zip с лимитами и защитой от zip-slip, install.json). Его копирует в `installer/lib` `scripts/prepare.js`; правьте только `src/`.
- `src/updater.js` — логика лаунчера: проверка при старте, «Позже» (3 раза на версию, хранится в settings.updateLater), установка. Источник — `src/app-config.json` (`repo`, пишет `scripts/prepare.js` из `TOTEM_REPO`) либо `repo` из `install.json`, который записал установщик.
- Релиз на GitHub: тег `vX.Y.Z`, файл `TotemLauncher-X.Y.Z-win-x64.zip` (корень архива = содержимое win-unpacked). Контрольная сумма — `digest` ассета GitHub или файл `.sha256`; без суммы обновление отклоняется.
- Сборка: `npm run dist` = `prepare` → `build-app` (electron-builder --win dir + zip) → `build-installer` (portable exe). Кросс-сборка на Linux работает без wine (`signAndEditExecutable:false`; иконка ярлыков берётся из `resources/icon.ico`, у exe при такой сборке значок Electron). В CI (windows-latest) иконка и версия exe выставляются штатно.
- Не меняйте `name` в package.json и не добавляйте `productName`: от этого зависит папка данных `%APPDATA%\totem-launcher`.
- Тесты: `tests/updater.js` (ядро). Живые прогоны (Electron под Xvfb, поддельный GitHub) делались скриптами на Playwright `_electron`; на Windows сам exe автоматически не проверялся.

## Договорённости
- Все данные пользователя в `app.getPath('userData')`; пути из интерфейса проверяются (нет выхода за папку).
- Любая сетевая загрузка: HTTPS, проверка хэша, запись в `.part` и переименование.
- Интерфейс: тёмный пиксельный стиль (см. «Дизайн»), иконки только пиксельные из `icons.js`.

## Проверено и нет
- Логика покрыта тестами в `tests/` на подменённых серверах.
- НЕ проверялось на реальной Windows и реальных серверах: окна и анимации, запуск игры (особенно 1.16.x), Forge/NeoForge-установщики, Modrinth/CurseForge/Ely.by/optifine.net, Telegram, 3D-просмотр скина.
- Хрупкое: скачивание OptiFine (разбор страницы сайта), ключ CurseForge нужен пользователю.

## Не сделано
Вход через Microsoft (закрыт), рисование прямо в 3D, предпросмотр скина при наведении, Quilt-сборки.

## Дизайн (v0.16): пиксельная тема
- Все цвета интерфейса считаются от одной переменной `--h` (оттенок, по умолчанию 272 = фиолетовый) в начале `app.css`: `--a/--a2/--a3` (акцент), `--e/--e2` (рамки), `--panel*` (фоны панелей). Не пишите в CSS жёсткие цвета для рамок/акцентов — берите переменные, тогда смена темы работает везде.
- Тема: `theme.js` (подключён во всех трёх окнах) читает `themeHue` из настроек и ставит `--h`. Выбор в «Настройки → Внешний вид»: пресеты, свой цвет (из него берётся только оттенок — читаемость всегда сохраняется), сброс. Применяется сразу, сохраняется с задержкой 350 мс; `main.js` проверяет `themeHue` (0–360).
- Пиксельные рамки — без картинок: несколько `box-shadow` со смещением по четырём сторонам (углы срезаны ступенькой) + тёмная внешняя линия. Цвет рамки задаёт `--fe` (при наведении `--fe:var(--a)`), доп. свечение — `--fx`. Закруглений нет нигде (кроме эллипса-платформы под скином).
- Полоса при наведении на кнопки — `::before` (ступенчатая SVG-полоса в `background`, анимация `steps()`), лежит под текстом и иконками (`z-index:-1` внутри `isolation:isolate`).
- Кнопка «Играть» всегда зелёная (не зависит от темы). Аура вокруг неё — `aura.js`: два холста 174×76, растянутые без сглаживания; цвет берётся из `--a/--a2/--a3`, при выключенных анимациях рисуется статично.
- Иконки 16×16 (главная, загрузки, сборки, настройки, телеграм, обновить, стрелки, играть, закрыть, свернуть, каталог, куб) лежат в `G2` в `icons.js` со своей палитрой `PAL2`; остальные — прежние 12×12.
- Фон по умолчанию — портал (`assets/bg/portal.jpg`) во всех вкладках; старые фоны остаются вариантами для главной. На вкладках кроме главной поверх фона темнее подложка (`body[data-page]`).
- Тотем (`assets/totem.png`) без вшитой зелёной обводки: обводка и свечение рисуются через `filter: drop-shadow` цветом темы.
- Окно без закруглений (`.win{inset:0}` + пиксельная рамка в `.win::before`).

## Настройки (v0.17)
- Вкладка «Настройки» = левое меню разделов (`.stnav`, кнопки `.sti`) + панель `.stmain` с секциями `.ss` (Игра, Кастомизация, Файлы, API ключи, Обновления). Строка настройки — `.sr` (иконка · название/описание · переключатель `.sw` или другой элемент). Любой элемент с `data-k=<ключ>` сам читается/сохраняется через `settings:get/set`.
- Новые ключи настроек (проверяются в `settings:set`): `showAfterExit` (открывать лаунчер после выхода из игры; «скрывать при запуске» — прежний `minimizeOnPlay`), `bgBlur`, `bgBright` (30–130), `notify` (ошибки показываются всегда), `hoverFx`, `transFx`, `themeSat` (0 = серая тема; цвета считаются от `--h` и `--s`, в CSS пишите `hsl(var(--h) calc(N% * var(--s)) L%)`).
- Свой фон: `bg:pick` (диалог → проверка сигнатуры → копия в `<данные>/backgrounds/custom.png|jpg`, большие уменьшаются до 2560 px), `bg:clear`; адрес отдаёт `settings:get` в `bgCustomUrl`. `bg.js`: `setCustomBg`, `setBgLook` (яркость/размытие через `--bgb`/`--bgbl`).
- Эффекты выключаются классами на `body`: `noanim`, `nohover`, `notrans`; всё применяет `applyUi()` в app.js.
- Иконки для настроек (gamepad, palette, files, key, ram, eyeoff, winback, sparkle, windows, shortcut, image, drop, sun, brush, bell, cursor, eye) — в `icons.js`.

## Главное меню (v0.18)
- Шапка: вкладки — только иконки (`.tab > .pi + .tl > .tt > b`). Название выезжает через `grid-template-columns: 0fr → 1fr` (`.tab:hover`, `.tab.on`); отдельного ползунка `.ind` больше нет, подсветка у самой `.tab.on`. «Каталог» — вкладка-кнопка (`data-p=cat`), открывает окно каталога (`openCat`), страницей не является.
- Главная: справа колонка `.rcol` = рамка `#skcard` + кнопка выбора `#ddb`. Внутри рамки две панели (`#skpn1` скин, `#ddm` выбор сборки), класс `bsel` на `#skcard` сдвигает их по вертикали (`bOpen()` в app.js; закрывается по выбору, повторному клику, клику вне, Esc и при смене вкладки). Окно «ещё одно окно» по-прежнему использует старый выпадающий список `.ddm`.
- Скин на главной приближён на 3 шага колеса: `z = 80 · 0.9³` (`Vh.set` в app.js).
- Картинки-иконки (`IMG` в icons.js): `grass` (блок земли), `tg`, `camera`, `steve` — PNG в `assets/icons/`; в сборках/загрузках везде используется `grass`.
- Рамки: к тройному/двойному контуру добавлены слой `--fd` (тёмно-фиолетовый) и фаска `--fh` (светлый верх-лево, тёмный низ-право); панели получили шум-текстуру (`--tex`) и уголки (`::before` у `header`/`.glass`). Кнопка «Играть» и аура не менялись.

## Окошко загрузок, каталог-вкладка (v0.19)
- Загрузки показывает окошко `#dm` слева внизу (`DM` в app.js): источники — состояние игры (`GS`: preparing/downloading/installing) и очередь заданий каталога `dmRun(title, fn)` (по одному; пока качается игра — «Ожидание»). Пока `dmBusy()`/`gameDl()` — «Играть» заблокирована (и в main.js `game:play` игнорируется, пока идёт `catJob`). Центрального окна `busym` больше нет.
- `runTasks` отдаёт `files/filesTotal` («5/87 файлов»); пауза — `Game.setPaused` (`PAUSE`/`gate` в game.js: не берутся новые файлы, чтение потока стоит, таймер простоя снимается), IPC `dm:pause`. Во время установщика Forge пауза недоступна. Отмена снимает паузу.
- Свёрнутый вид — кнопка `#dmmini`; классы `dm-x`/`dm-m` на `body` сдвигают `.barp` и `.quick`, чтобы окошко ничего не перекрывало.
- Каталог — страница `#p-cat` (`catPage()`), вкладка скрывает нижнюю панель (`nobar`). Иконка каталога — `assets/icons/catalog.png`.
- `loaders:avail` возвращает `ok` (ответили все три сервера); интерфейс повторяет запрос каждые 8 с и по событию `online`, так же список версий (`loadAV`, `loadV`).
- Настройка `playAura` (по умолчанию true): класс `noaura` на `body`, `aura.js` не рисует.


## Новости Minecraft, отмена загрузки каталога (v0.20)
- **Новости** (главная, слева): `src/news.js` (главный процесс) + `src/ui/news.js` (отображение). Источник — официальные данные Mojang: `launchercontent.mojang.com/news.json` (новости сайта) и `/v2/javaPatchNotes.json` (списки изменений: релизы и снапшоты новее последнего релиза). Формат ответов Mojang не документирован — разбор терпимый, при сбое одного источника работает второй, при сбое обоих — надпись «Нет подключения / Не удалось загрузить» и кнопка «Обновить».
- Список: по 15, «Показать ещё» добавляет ещё 15; фото листаются сами каждые 5 с (пауза при наведении на фото); у списков изменений фото из текста подгружаются в фоне (`news:imgs`). Автообновление: при запуске, каждые 10 минут, через 2,5 с после выхода из игры, при появлении сети, кнопка «Обновить» в шапке (принудительно). Если фоновое обновление не удалось — старый список остаётся.
- Стрелка в шапке: полный оборот, рамка уезжает влево, остаётся краешек шапки со стрелкой (клик по нему открывает обратно). Состояние хранится в настройке `newsHide`.
- Подробности: клик по новости (кроме фото) или «Узнать больше»; текст проходит очистку (`sanitize` в news.js: только p/h/ul/ol/li/b/i/code/blockquote, картинки только с minecraft.net/mojang.com). Кнопка «Читать на сайте» открывает статью (WEB_OK расширен на minecraft.net, mojang.com).
- **Перевод** (настройка `newsRu`, по умолчанию вкл.): заголовки, описания и текст отправляются в Google Translate (`translate.googleapis.com`, без ключа), результат кэшируется в `news-translate.json`. Не получилось — остаётся оригинал. Сервис неофициальный, формат может измениться.
- Безопасность: картинки новостей разрешены в CSP/`hardenSession` только для хостов Mojang; запросы за новостями делает главный процесс; из окна приходят только id новостей (`^n[0-9a-f]{12}$`). Для автотестов и скриншотов `TOTEM_NEWS_BASE=http://127.0.0.1:порт` подменяет сервер (работает только из исходников, не в собранной программе).
- **Отмена загрузки каталога**: кнопка ✕ в окошке загрузок. `cat:cancel` обрывает все идущие задания (`AbortController` на каждое `catJob`), недокачанные и скачанные в этом задании файлы удаляются (файлы, что были до него, не трогаются), недосозданная сборка (modpack) удаляется. Задание, ждущее очереди, просто пропускается. Для загрузки игры кнопка работает как «Отмена» внизу. Тесты: `tests/catcancel.js`, `tests/news.js`.

- **Окно «на весь экран»** (v0.21): кнопка между «Свернуть» и «Закрыть» (`#wmax`). Главный процесс (`setWinMax` в main.js) растягивает окно на рабочую область экрана и запоминает прежние границы; повторное нажатие возвращает плавающее окно. ## Каталог скинов (v0.22)
- **Где**: вкладка «Скин» → третья кнопка «Каталог» рядом с «Мои скины» и «Редактирование» (`#skt.s3`, панели `.skp` в `.skr` шириной 300%). - **Данные** (`src/skincat.js`, главный процесс): `GET {api}/skins`, `GET {api}/skins/{id}.png`, `POST {api}/skins/{id}/download` (протокол и пример сервера — `skin-server/`, README внутри). Адрес — `skinsApi` в `src/app-config.json` (при сборке `TOTEM_SKINS_API=https://…`, только https). Пустой адрес → встроенный стартовый набор `src/skincat-data/` (16 скинов), счётчик скачиваний локальный (`<данные>/skincat/counts.json`). Ответы сервера недоверенные: id по маске `[A-Za-z0-9_-]{1,40}`, строки очищаются от тегов и обрезаются, до 3000 записей, PNG проверяется `Skins.check`, редиректы запрещены. Последний удачный список кэшируется (`skincat/list.json`), картинки — в `skincat/png/`; нет сети → показывается кэш (`stale`), без кэша — сообщение и «Обновить». Для автотестов/скриншотов `TOTEM_SKINS_BASE=http://127.0.0.1:порт` (только из исходников).
- **Скачивание**: `skins.put({…, from: <id каталога>})` → отдельный скин в «Моих скинах»; «скачан» = в `skins.json` есть запись с `from`. Повторно, пока копия существует, не качается и счётчик не растёт; удалили копию — можно снова.
- **Карточки** (`src/ui/skincat.js`): сетка ровно 4 в ряд, карточка 3:4. Один общий WebGL-контекст (`Skin.makeSheet()` в skin.js) рисует карточки по очереди и копирует кадр в их 2D-холсты — столько отдельных контекстов браузер не потянет. Рисуются только видимые (`IntersectionObserver`); пока вкладка/страница не активна или открыто окно скина, цикл стоит. Карточки подгружаются по 24 при прокрутке, картинки — пачками по 24 через `skcat:png`.
- **Вращение**: вне наведения угол = `OM·t` от общих часов + смещение `o`, которое плавно (`exp(-5t)`) сходит к нулю — все свободные скины всегда синхронны, а после ухода мыши скин плавно возвращается в общий ритм. При наведении тело и голова следят за мышью (`tx/ty` ∈ [-1,1] относительно рамки), вращение стоит.
- **Окно скина** (`#skm`): отдельный `Skin.makeViewer` (вращение мышью, колесо — масштаб, переключатель внешнего слоя), подробности, «Скачать» → «Уже в «Моих скинах»» + «Применить».
- Фильтры: сортировка (популярные/новые/старые/по названию), руки (Classic/Slim), период, автор, «Скрыть скачанные», поиск по названию и автору.
- Тесты: `tests/skincat.js`. Не проверялось на реальной видеокарте и реальном сервере (ручной прогон — Electron под Xvfb с программным WebGL и `TOTEM_SKINS_BASE`).

Включённые и выключенные моды, ресурс-паки, шейдеры. Не входят: файлы, добавленные вручную (показываются предупреждением), датапаки и карты. Установка: `GET /v2/versions?ids=`, проверка хоста/имени/sha1, при ошибке или отмене сборка не остаётся. Загрузчик берётся последней версии. Тесты `tests/share.js` (+ в `mock-net.js` версии с id, `/version_files`, `/versions`, `/projects`).
- **Общие настройки игры** (`src/optsync.js`, настройка `sharedOptions`, по умолчанию включена): после выхода из игры options.txt сборки запоминается в `shared-options-<legacy|modern>.json`, перед запуском любой сборки значения подставляются. Не общие: ресурс-паки, последний сервер, размер окна, служебные отметки. Тест `tests/optsync.js`.
- **Полный сброс данных** (`src/reset.js`, `main.js: app:reset / runReset`, окно `ui/reset.html`): кнопка внизу Настройки → Игра. Основной процесс останавливает игру и запускает помощника (`--totem-reset=<папка> --wait-pid=… --user-data-dir=<tmp>`), закрывается; помощник ждёт его выход, удаляет всё в `%APPDATA%\totem-launcher` (ссылки не разворачивает, занятые файлы пробует повторно), показывает прогресс и запускает лаунчер заново. Папка установки лаунчера не затрагивается. Проверка: имя папки должно быть `totem-launcher`. Тест `tests/reset.js`.
